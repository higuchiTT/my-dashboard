# dashboard.html・css/・js/ 修正後チェックリスト（Stop hookによる強制チェック）

dashboard.html・css/・js/ を編集したため、完了報告の前にこのチェックリストの全項目を確認してください。
各項目について「✅ 確認済み」または「⚠ 修正した」を明示してから完了と報告すること。
形式的な羅列ではなく、実際にコードを見て判断する。

## 1. クリック領域の両立
- テキスト・✏ アイコンをクリック → インライン編集が起動するか
- セル余白・chevron・⠿・# 列・カラム間 → 行展開が起動するか
- どちらの操作も意図通り動くかメンタルシミュレーションする

## 2. 入力欄の幅
- `flex:1` で無闇に広がっていないか
- `size` 属性または `width:fit-content` で内容に合った幅か
- 入力欄が広すぎて「行展開クリック領域」を潰していないか

## 3. カラム幅配分
- 品名・カテゴリ等は最小限の幅、余りはメモ欄が引き受けているか
- `minmax()` と `fr` の合計バランスは妥当か
- 列ヘッダーと行の列数が一致しているか

## 4. 行の高さ統一
- 内容差（1行 vs 2行、説明あり/なし）で行高がバラついていないか
- `height` 固定 + `align-items:center` で統一されているか

## 5. 数値の右揃え
- 金額・予算は `text-align:right` または `justify-content:flex-end`
- 固定幅にして桁が揃って見えるか

## 6. stopPropagation の網羅
- 編集起動要素（.editable-text, .edit-pencil 等）
- select 要素（status-sel, cat-sel 等）
- input・textarea
- 削除・保存等のボタン
- すべてに `event.stopPropagation()` または closest チェックが効いているか

## 8. 品名・カテゴリ・予算・ステータス列の最小幅
- 品名・カテゴリ・予算・ステータスの各列に `min-width` または `minmax(Npx, ...)` が設定されているか
- ウィンドウを狭めたとき、これらの列が改行されず最小幅を保持しているか
- メモ列だけが改行・縮小を許容する設計になっているか

## 7. 不要要素の完全削除
- 「いらない」と言われた要素が HTML から消えているか
- 対応する CSS クラスも消えているか
- JS のハンドラ・state も消えているか（残骸のコメント・関数含む）
